# 箱庭コア信頼性修正

実施日: 2026-10-04

## 対応内容

- `useGardenStore` の庭編集、Undo/Redo、観察編集、写真リンク、状態置換、再読込を同じ直列化境界に統合した。
- 保存操作は呼び出し時のユーザースコープと世代を保持する。スコープ変更後に完了した旧操作は、新スコープの表示状態・履歴・保存表示を更新しない。旧操作の保存先も呼び出し時のスコープのままとする。
- 同一スコープの状態置換は先行保存の後に実行し、最後に永続化された置換状態が古い保存で上書きされないようにした。置換・再読込時は Undo/Redo 履歴を破棄する。
- `latestStateRef` の render 中代入を廃止し、永続化成功または読込成功時だけ同期更新する。連続操作は直前に保存成功した状態を基に計算する。
- Undo/Redo で配置情報を復元するとき、配置中・収納中を横断して同じ plant ID の現在の `observationIds` を維持する。復元される植物のリンクは、現在も存在する観察だけを保持する。
- `saveState` の画像保存を含む全処理とストア側の永続化呼び出しで throw を `SaveResult` に変換する。失敗時は日本語エラーを設定し、状態・履歴を進めず、配置中 busy 状態を解放して再試行できる。

## 追加回帰試験

`src/test/gardenStoreReliability.test.tsx` に次を追加した。

1. 保留中のゲスト保存後にスコープ変更・再読込しても、旧庭と Undo 履歴を新アカウントへ反映しない。
2. ベンチ配置後に追加した明示的写真リンクを、ベンチの Undo/Redo 後も保持する。
3. reject された保存が必ず失敗結果と日本語エラーで完了し、状態・履歴を保持して次の保存を再試行できる。
4. 配置確認中の throw 後に busy 状態を解放し、同じ配置を再試行できる。
5. 高速な連続編集が保存済み最新状態へ順番に積み上がる。
6. 保留中編集と状態置換を直列化し、置換状態を最終保存して古い履歴を破棄する。
