# おでかけ・招待状の独立ブラウザ確認

2026-10-04 JST。対象は c771 の未コミット統合全体、プレビューは `http://127.0.0.1:5186/`。ユーザーのブラウザとは別の agent-browser セッション `visits-review` を新規作成して確認した。公開・コミットは行っていない。

## 結果

- 見本一覧から「丘と水辺の植物園」「静かな水辺の庭」「バラの中庭」の3件を開き、それぞれが別の実3D庭として描画された。訪問中は編集、撮影、記録、設定の操作を表示せず、「見るだけの訪問」、全景、戻る、自分の庭への導線だけを表示した。
- 丘と水辺の植物園でモミジを実際にタップし、和名、学名、紹介文を表示した。キャンバスを200pxドラッグすると前後の画面で13.99%の画素が変化し、回転操作が反映された。
- 自分の庭からタイトル「検証の庭」、作者「訪問テスト」のKG1招待状を作成した。コードは2,439文字で、復号した最上位項目は `version/title/author/soilTiles/plants/decorations` のみ。植物にも `id/tileId/color/rotation/modelType` だけが入り、観察ID、写真、メモ、収納、同期情報は含まれなかった。
- `KG1.invalid` は日本語のエラーを表示し、入力を残したまま訂正できた。その後に正しいコードを貼り付け、同じタイトル、作者、25枚の地面、チューリップ1本の庭を訪問できた。
- 訪問前に作った自分の庭のIndexedDB行をSHA-256で記録した。3つの見本、招待状の庭、明示的な帰宅、再読込の後もハッシュ `937b5b255a317e1e161d94cae4ac08b1827f137181fc35d856e947a48c9cf9bc`、revision 1、updatedAt、植物ID、位置、向きが完全に同じだった。
- 390×844と320×568で横方向のはみ出しは0px。訪問画面の戻る、全景、自分の庭へは44px高で画面内に収まり、320pxでも見出しと左右ボタンは重ならなかった。植物紹介カードは390pxでフッターの上に収まった。見本一覧と招待状フォームは縦スクロールでき、320pxで招待状作成ボタンは初期表示内、貼り付け欄と訪問ボタンはスクロール後に到達できた。
- 最初の確認でブラウザの戻るがアプリ外へ移動する問題を検出した。修正後の新規セッションで、`自分の庭 → おでかけ → 訪問` に対してブラウザ戻ると進むが各1階層を往復すること、画面内の戻る後にブラウザ戻ると自分の庭へ戻ること、「自分の庭へ」で直接帰宅した後に古い訪問が再表示されないことを再確認した。
- 最終の新規読込セッションでブラウザ例外は0件。Three.jsの既知の非推奨警告は例外として数えていない。
