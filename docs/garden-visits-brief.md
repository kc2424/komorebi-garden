# おでかけ・招待状・庭の上限

2026-10-04。今回の依頼に対する実装仕様。正本は c771 の未コミット変更を含む作業ツリー。5186 を継続使用し、公開・コミットは行わない。

## 体験

自分の庭 → おでかけ → 見本を選ぶ → 3Dで回して眺め、植物を見る → 自分の庭へ戻る。前回の作例画像の庭を実際に訪問できる。ほかに水辺とバラの中庭を用意し、小さな敷地でも違う表現ができることを示す。

招待状は作成時の配置を含む文字列。相手が同じ更新版のアプリへ貼り付けて訪問する。短いサーバー照会コード、オンライン一覧、リアルタイム同時プレイではない。未公開の更新に対して既存公開URLで機能すると案内しない。

参考にするのは、訪問先を安心して眺められ、元の庭へ影響しない仕組み。任天堂が説明する「夢の島」の分離という考え方を、このアプリの小さな庭と非同期の招待状へ応用する。キャラクター、画像、音源、文章やゲーム固有の名称は流用しない。
参照: https://www.nintendo.com/jp/topics/article/ac44773d-9db3-4374-90f2-4782589f051f

## 上限

| 項目 | 上限 |
| --- | --- |
| 敷地 | 中心から各方向4マス、9×9、81マス |
| 高さ | 0〜3、4段階。1段0.32の既存仕様 |
| 配置 | 植物と飾りを合わせて64個、1マス1個 |
| 収納 | 今回は数を制限せず、取り除いた物や写真の紐づけを保持 |

既存の大きな庭を切り詰めたり、読み込みで拒否したりしない。追加だけを制限し、移動・収納・撤去は引き続き可能とする。植物20種類・飾り12種類・地面6種類はカタログの種類数であり、配置個数とは区別する。操作ガイドと残り数を編集画面へ表示する。

## データ契約

訪問先は App の一時的な訪問状態へ保持する。自分の GardenState、IndexedDB、undo/redo、画像保存、同期へ渡さない。既存の Garden3DCanvas を専用の閲覧画面で使用し、編集や写真記録の操作を出さない。戻る、ホーム視点、植物紹介、タッチ回転を提供する。

招待状 KG1 はバージョン付きのbase64url JSON。上限40,000文字以内、圧縮なし。配置だけを許可リストで再構成し、IDも振り直す。写真・メモ・観察ID・画像参照・収納・アカウント・同期情報を含めない。タイトル40文字、作者24文字。既知モデル、色、地面、整数座標、高さ、有限な回転、参照、重複、重なり、個数を検査する。不正入力は日本語で案内し、描画や保存に進めない。

## 受け入れ

1. 作例と異なる2つの見本を実3Dで訪問し、全景・回転・植物紹介が使える。
2. 自分の庭から招待状を作り、別の保存領域で貼り付けて同じ配置を見られる。
3. 不正な招待状から訂正して復帰でき、コピー失敗時も文字列を選択して渡せる。
4. 訪問の前後・アプリ再起動後に自分の庭、観察ID、保存revisionが変わらない。
5. 境界・65個目・高さ上限がUIと保存操作で一致。収納・復帰・Undoを壊さない。
6. 320/390pxのスマホ、タブレット、PCで主要操作に到達。iPhone/iPad Simulatorで訪問と帰宅を実操作する。
7. 適切な単体・統合テスト、build、API型検査を行い、実機や公開サービスの未検証と区別する。
