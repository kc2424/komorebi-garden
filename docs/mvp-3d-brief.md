# チューリップ1種類から始める3D庭MVP

決定日: 2026-09-08。ユーザー承認済み。本書は旧2D体験版briefより優先する。企画書原本は保存する。

## 体験と役割

屋外の発見が知識・写真・思い出として残り、自分だけの小さな世界を作る材料になる。指で裏側まで回せる本物の3D庭。Minecraftの自由な組み立て方を参考にし、見た目は角の丸い土とアニメ調の花。Astraは仕様・判断・核心レビュー、実装・技術調査・実験はCursor CLI composer-2.5。ユーザーが最終植物モデルを制作するが、仮モデルで実装を進める。

## 今回の完成条件

1. 写真を撮影/選択し、単一植物識別APIの候補を確認できる。庭に対応するのはチューリップのみ。色はユーザーが確認・変更できる。曖昧/別植物/通信失敗をチューリップに自動変換しない。
2. 写真・日付・名前・色を観察として保存。再発見は新しい観察になり、庭の本数とは独立する。未対応植物も観察保存できる。
3. 発見で解放したチューリップを複数自由に植える・移す・しまう。撮影を本数獲得のノルマにしない。
4. 小さな平面の土タイルを足す・外す。編集中は配置位置が分かり、普段はほんわかした箱庭。土削除時は植物を失わず、観察は常に保持する。
5. タッチ/マウスで庭を回し裏まで見られる。再読込後も庭・観察が残る。既存の保存記録を消さない。
6. 実写真の識別を試した証拠と、3D庭の配置/編集/保存の検証結果を記録。APIキー未設定やユーザーモデル未受領を完成扱いしない。仮モデルとしての体験検証は進める。

## 実装順序

1. Cursorが公式資料から単一識別APIの接続方法・費用・制約を短く調査。認証が利用できる場合だけ既知の植物写真で実検証。資料上の情報と実測を分ける。キーがなければ報告し、接続コードと残りを先に進める。
2. 仮チューリップで回転、自由配置、土タイル編集、保存を作る。
3. 受け渡し仕様をMDに記載（GLBを候補に、単位/原点/花の色変更部分）。ユーザーのモデルは後で差し替え可能にする。
4. 写真→確認→観察保存→庭で植えるをつなぐ。モックと本番の区別をUIにも保持。
5. 関連テスト・build・ブラウザで一周検証。核心の失敗だけ修正する。

## 制約と停止条件

実績解放、植物追加、高低差、水辺、地図、共有、認証・課金、自作CNN、写真からの3D自動生成は後回し。色推定を別のAI課金に増やす必要はなく、初回は明示的な色確認でよい。土/花/道以外の装飾を広げない。大きなバックエンド基盤を作らず、キーを保護する最小のAPI経路のみ。

Cursor実装→核心レビュー→必要修正のループ。基本条件を満たしたら磨き続けない。外部キー/モデル/追加費用が必要な場合は具体的な手順と残件を提示し、独立作業を終えておく。実ユーザーによる気持ちよさの確認は開発検証と分ける。
