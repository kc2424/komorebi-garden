# 箱庭植物20種の軽量化と描画計測

2026-10-04 JST。対象は c771 の `codex/garden-viewing-preview` にある既存統合を含む作業ツリー。20種類の植物を、1本につき1つの結合メッシュと共有材質で描画する。全種を1本ずつ置いた植物部分は14,488三角形。MacのChromiumで全種・全飾りを並べた庭を観測し、形状数と描画状態を確認した。観測で見つかった接地影の繰り返し描画を、庭の内容が変わったときだけの再計算へ変更した。

## 共有と静的プレビュー

- `LightweightPlants.tsx` の通常植物は同じ `MeshStandardMaterial` を共有し、色は頂点属性に保持する。読み込み後の実シーンでも20本に対して材質の一意数は1だった。
- ジオメトリは種類単位でキャッシュする。チューリップだけ保存色6種ごとにキャッシュし、他の種類は保存された色スロットが違っても同じジオメトリを使う。植物の退場時に共有リソースを破棄しない。
- 通常の植物本体は1描画呼び出し／1レンダーパス。選択リングが表示されると別途1回増え、影のパスでも植物が描画される。1本がフレーム全体で常に1回という意味ではない。
- ゴーストは共有された半透明材質で描画し、影を落とさない。植えた後は通常の材質へ切り替わる。
- カタログは同じ3D形状を投影した静的SVGを表示する。20種＋チューリップの追加5色＝25ファイル。合計1,901,617 bytes、各ファイルを個別gzip圧縮した合計は204,076 bytes。gzip値はローカル圧縮による参考値で、配信サーバーがその方式を使う保証ではない。
- カタログを表示するためのWebGLキャンバスは追加しない。`scripts/generate-plant-thumbnails.ts` でSVGを再生成できる。植物本体にも画像テクスチャや外部モデルの取得は必要ない。

花房、ベル形、細い花穂、球状の花、葉の束、広葉、枝と樹冠などで輪郭を変えた。色違いだけで20種類と数えていない。旧データの `tulip`・`cosmos`・`pansy` と、モデル省略時のチューリップ扱いを維持する。写真の関連IDは変更しない。

## Blenderを今回使わなかった理由

今回の必要形状は既存Three.jsの球・円柱・葉と花びらの小さな面で表現できた。手続き形状を結合する方法なら、形状・色・カメラ用の高さ・静的プレビューを同じソースから管理でき、モデルやテクスチャの追加ダウンロードも不要だった。Blenderは複雑な有機形状や美術調整を作り込む段階で有効な候補だが、今回の20種を軽く追加するための必須工程ではなかった。Blenderそのものが重い、手続きモデルなら常に速い、という比較結果ではない。

30通知ごとに記録した20回のサンプルでは、calls・triangles・geometries・texturesは同じ値を保った。上記のgeometry・texture数は庭全体の値であり、植物だけの数ではない。

この測定は高性能なMac上で、全景を静止させた状態の短時間観測である。rAFの通知頻度はGPUの実処理時間、入力遅延、電力、長時間の発熱を直接測ったものではない。iPhone実機のFPS、低価格Android、Safari、DPR 2以上の性能を検証した結果ではない。実機の性能判定は別途必要。

## 影の再計算を庭の変更時だけにする

`Garden3DCanvas.tsx` の接地影を、メモ化した `GardenContactShadows` と `frames={1}` に変更した。`getGardenShadowRevision` が土台の座標・表面・高さ、植物と飾りの種類・配置・回転、選択リングや仮置きの形を追跡し、変化があると1回再計算する。カメラ位置、空、観察写真の関連、色だけの変更では影の形は変わらない。

固定利用しているDrei 10.7.8は、コンポーネントの再描画で内部のフレームカウンターがリセットされる。これをメモ化で制御し、影のRenderTargetを保ったまま更新する。Reactのkeyによる毎回の再マウントは行わない。512pxの解像度、ぼかし2.8、不透明度0.22、色は従来と同じ。Drei更新時には、この再描画とカウンターの動作も再確認する。

同じバックアップを読み込んだ専用セッションで、実際の「道・地面 → 高くする」から地面を変更し、眺めるへ戻った。その後、編集の「取り消す」で戻し、カメラをドラッグして回した。既存の影RenderTargetからRGBAを読み取り、ハッシュとアルファ合計を比較した。

| 操作後の状態 | 影画像のハッシュ | アルファ合計 | 61回のrAFに対するrenderer.frame増分 |
| --- | ---: | ---: | ---: |
| 編集前 | 1,290,949,498 | 12,188,493 | 61 |
| 地面を1段高くする | 367,617,638 | 12,174,332 | 61 |
| 取り消して元の高さへ | 1,290,949,498 | 12,188,493 | 61 |
| カメラを回す | 1,290,949,498 | 12,188,493 | 61 |

地形変更で影が更新され、取り消しでは元の影のハッシュへ戻った。カメラ回転では影が変化しなかった。4回すべてで影のtexture UUIDは同じで、庭全体のtexture数も8を維持した。生の読み取り記録は `verification-2026-10-04/contact-shadow-*.json` に保存した。

## 確認した回帰

植物追加時に `lightweightPlants.test.ts`、`previewCamera.test.ts`、`plantingFlow.test.ts`、`v2LinksModels.test.ts` の23テストが合格。20種の形状の相違、三角形予算、有限な頂点属性、地面からの高さ、キャッシュの共有、静的ファイルの存在、旧モデルの互換を確認した。統合後の全体テストとbuildの結果は全体の検証記録で扱う。

接地影の変更では、形状に関係する変更でrevisionが更新され、写真リンクや同等の状態では更新されないことを4テストで確認した。カメラの15テストと合わせて19件が合格し、型検査も合格。raise-terrainと直接配置のハイライトを追加した最終helperでも4テストを再確認した。
