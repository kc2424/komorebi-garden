# 庭へのおでかけ・招待状 実装記録

実装日: 2026-10-04（レビュー反映: 2026-10-04）

## 動作すること

- 自分の庭の下部ナビから「おでかけ」を開き、3つの「見本の庭」をサムネイルから選べる。
- 「丘と水辺の植物園」は `docs/verification-2026-10-04/expanded-garden.json` の49土地・20植物・12飾りを使用する。作例画像に合わせ `(-1, -2)` の土地は高さ2。きのこ飾りは `(-3, -2)` の草地に単独配置。
- 5×5の「静かな水辺の庭」と7×7の「バラの中庭」も、植物・地面・飾りを実データとして配置している。カード画像は `public/samples/waterside-garden-example.jpg` と `public/samples/courtyard-garden-example.jpg`（実機キャプチャ）を使用する。
- 訪問画面は既存の `Garden3DCanvas` を1つだけ使用する。自由回転、植物タップ時の名前・学名・特徴表示、「庭全体を見る」、ギャラリーへ戻る、自分の庭へ戻る操作に対応する。
- 訪問データは画面内の読み取り専用スナップショットで、ストアの置換・保存・同期を行わない。訪問中は自分の庭のCanvasがアンマウントされる。
- Escapeは植物カードを先に閉じ、カードがなければギャラリーへ戻る。
- アカウント範囲が変わった場合は、選択中の訪問情報とブラウザ履歴マーカーを破棄し、自分の庭へ戻す。
- 招待状は `KG1.` + base64url UTF-8 JSON。庭名、作者名、土地、配置中の植物と飾りだけを含む。
- 招待状の作成・貼り付け訪問、Clipboard API、コピー失敗時のテキスト選択、対応端末での手動共有に対応する。
- 招待状の解析は生の入力長が40,000文字を超える場合はトリム前に拒否し、続けてトリムする。版、既知の植物・飾り・色・地面、座標、高さ、回転、ID・座標重複、配置先、1土地1配置、`GARDEN_LIMITS` に沿った土地・配置上限を検証する。
- 招待状から復元した訪問の `id` はペイロード全体の決定的なハッシュ（FNV-1a 風）で、内容が違えば別ID・同じ招待状なら同じIDになる。
- 写真、観察ID、メモ、収納、同期・アカウント情報、元の内部IDは招待状に含めない。解析後のIDと土地リンクは再生成する。
- 庭づくり画面に「土地 n/81・配置 n/64・高さ4段・9×9内」を表示する。旧データが上限外でも削除せず、移動・収納できることを案内する。

## ブラウザ履歴（おでかけ専用）

- ルーターは使わず、`history.state` に `komorebiVisits` マーカーだけを追加する。既存の `history.state` フィールドはスプレッドで保持する。
- 自分の庭 → おでかけ: `pushState({ layer: 'outings' })`
- おでかけ → 訪問: `pushState({ layer: 'garden-visit', visitId })`
- ブラウザの戻る（`popstate`）: 訪問 → おでかけ → 自分の庭。訪問を離れるときは `selectedVisit` をクリアする。
- 訪問画面の「戻る」・おでかけの「自分の庭」・訪問の「自分の庭へ」は、現在のマーカーに対応する `history.back()` / `history.go(-2)` でスタックを消費し、二重に `pushState` しない。
- 訪問から「自分の庭へ」で帰るときはセッション内の訪問キャッシュも削除し、ブラウザの進むで復元不能な訪問を空白画面にしない。進むで訪問マーカーに当たっても復元できなければおでかけへフォールバックする。
- 初回ロード時に古い `komorebiVisits` が残っていれば `replaceState` で自分の庭に正規化する。
- ネイティブ戻るは下書き・確認・同期競合を優先したうえで、上記と同じ `leaveGardenVisit` / `leaveOutings` を使う。
- 実装: `src/utils/visitsHistory.ts` と `src/App.tsx` の `popstate` リスナー。

## 制限

- 招待状は作成時点のスナップショットであり、公開ディレクトリ、公開URL、利用者検索、閲覧数、ライブ同期はない。
- 写真とメモは意図的に共有しない。
- 端末のClipboard権限がない場合は自動コピーせず、コードを選択して手動コピーを案内する。
- Web Share APIがない端末では共有ボタンを表示しない。
- 見本の庭は作者付きの作例であり、実在する公開利用者の庭ではない。
