## 今回まとめて実装する範囲

1. **入口** — 初回案内は箱庭が主役。主CTA「庭づくりをはじめる」で編集へ直行。写真/ログイン不要。既存データは保持して再開する。写真記録・設定は副導線として残す。新規の土台は十分な広さを用意するが、既存庭を見本で置き換えない。
2. **花** — チューリップ・コスモス・パンジーを初めから自由に何本でも置ける。チューリップ6色。箱庭カタログで未解放/モデル見本を強調しない。実観察・見本写真の出自は書き換えず、写真との関連は既存の明示リンクのみ。
3. **地面と道** — 土・草・石の小径の3表面をタイル単位で塗り分けられる。隣接土台の追加/削除も維持。花/飾りを勝手に失わず、表面を戻せる。
4. **飾り** — ベンチ・丸い石・ランタンの3種類を手続き3Dで追加。既存の丸いアニメ調に揃え、外部アセット/追加依存に頼らない。単一タイルを占有、花との重なり不可、地面表面とは共存。実際の植物観察とは紐づけない。
5. **制作操作** — 分かりやすい「花 / 道・地面 / 飾り」の選択。ゴースト仮置き、有効/無効な場所の表示、回転、確定/キャンセル、同じ品を続けて置く。花と飾りの移動・回転・収納/復帰。土台を外す時は載っている物を収納し、記録は保持。スマホでもタップで完了できる。
6. **やり直し** — 庭の編集を少なくとも直前1手、できれば20手まで取り消し/やり直し。対象は庭の形・地面・花/飾り配置と収納のみ。写真、観察、認証、同期メタデータを過去へ巻き戻さない。保存失敗や連打で履歴と状態がずれない。別スコープ/遠隔状態の適用後は古い履歴を使わない。
7. **完成と再開** — 分かりやすい「眺める」で既存のカメラ/空を楽しめる。制作UIを片づける。自動保存中/保存済み/失敗が分かり、再読込して配置・向き・地面・収納が残る。新しいデータはバックアップと既存シリアライズでも失われない。

## Astra Ultraの実装レビュー上の重点

- 新規土台は5×5の小さな草地を目安に、既存庭の地形を変えない。カタログは3カテゴリと選択物の操作にまとめ、全体ツールを増やしすぎない。
- 道は連続して見える表面にし、草が石を突き抜けない。小物は草/道の上に置ける。可能なら石/砂利の2種、まず1種でも途切れない制作体験を優先。
- 保存を伴う編集は直列化または同期的busy refとlatestStateRefで連打による上書きを防ぐ。Undo/Redoも保存成功後だけ履歴を進め、現在の同期revisionを更新する。観察追加後にUndoしても写真を消さない。
- `App.tsx` の既存データ判定は花/観察だけでなく飾り/道だけの庭も考慮する。
- `persistence.ts` の `shouldAttemptLegacyMigration` は観察0件のv3を旧v2で再上書きする危険がある。既存v3を尊重し、旧キーが残る状態で箱庭のみ編集→再読込の回帰を確認する。
- チューリップの制限はカタログ・純粋アクション・plantingFlow・色UI全体で整合させる。既存tulipUnlocked値を無理にtrueにしたり、見本観察を自動生成して解放を偽装したりしない。
- 新規データは型定義だけでなく、検証・移行・保存/hydrate・バックアップ・同期シリアライズまで往復させる。遠隔DB/認証運用の変更は不要。
