## 認証メール

**最新結果（2026-09-10 10:10 JST）:** 本人了承済みの現在のGmail SMTPを設定し、住所のない日本語メールを実受信。OTPは8桁の既定値を6桁へ変更し、新規利用者・既存利用者の実メール認証でアプリにログインできた。自動引き継ぎは保存時の自己競合を検出したため修正・検証中。下記のSMTP未設定記述は設定前の経緯。

既存の専用Supabaseプロジェクト `ckdwboedxmdphhsyvnli` を使用する。管理画面では独自SMTPが未設定で、テンプレート編集にSMTP設定が求められることを確認済み。プロジェクトの重複作成、Proへの変更、DBマイグレーションの再適用は不要。

ユーザーは初期費用0円・住所を載せない方法を指定。Brevoの住所必須画面で手続きを止め、Gmail SMTPによる少人数検証を候補にした。利用するGmailと資格情報の保存を確認してから設定する。SMTP未反映、実メール・自動引き継ぎは未確認。[設定手順](email-delivery-setup.md)。

設定に必要なもの:

- メール送信サービスの利用可能なアカウント。
- 配信サービスが必要とする送信元の確認。初期Gmail検証では本人所有アカウントを使用する。独自ドメイン/DNSは本番構成を別途決定する場合の条件。
- サービスが発行するSMTPホスト・ポート・ユーザー名・認証情報、検証済み送信元アドレス。
- 受信を実際に確認できるテスト用メールアドレス。

秘密キー・SMTPパスワードは会話・リポジトリ・検証ログへ記録しない。サービスとSupabaseの設定画面、または既存の外部秘密情報管理で扱う。

準備後に行う作業:

1. 配信サービスで送信元とSMTP利用可否を確認し、SupabaseのAuthentication > EmailにSMTP設定を入れる。ドメインを使う構成に変更する場合は先にDNSで認証する。
2. パスワードレスメールのテンプレートに `{{ .Token }}` の認証コードを表示し、アプリのコード入力によるログインと一致させる。メールリンクだけのテンプレートを完成扱いしない。
3. 実メールの到達を確認したテスト環境で `VITE_AUTH_EMAIL_READY=true` を明示してビルドする。未準備の通常プレビュー・バイナリではfalseのままにする。
4. 初回送信→受信→ログインを確認する。誤コード、宛先変更、60秒後の再送、期限切れ、通信失敗後の復帰も確認する。

公式参照: [Email passwordless](https://supabase.com/docs/guides/auth/auth-email-passwordless)、[Custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp)。

ユーザーの既存保存領域を使わず、専用テスト領域A/Bとテストアカウントで実行する。

| 操作 | 合格条件 |
|---|---|
| Aでゲスト記録を作成してログイン | 写真・観察・配置・明示した観察リンクが保持される |
| Aで同期 | 実際のクラウド書込み後に「同期済み」となる |
| 空のBで同一アカウントへログイン | Aの写真・花の色/位置・観察リンクが復元される |
| Bを再起動して花をタップ | 同じ写真を開ける |
| Aでオフライン変更→復帰 | 未同期表示から正常に同期へ復帰する |
| A/Bを競合させる | 選択前の無断上書きがなく、選んだ庭を維持する |
| 別のテストアカウントへ切替 | 前のアカウントのデータが表示されない |
| テストアカウントを明示削除 | 写真・クラウド状態が削除され、旧セッションから復活しない |
