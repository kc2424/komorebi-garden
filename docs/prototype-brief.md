# デジタル植物園：体験検証プロトタイプ

> **歴史的ドキュメント（2026-09-08）** — 本書は旧2D体験版の仕様です。現行の実装仕様は [`mvp-3d-brief.md`](./mvp-3d-brief.md) を参照してください。

## 役割と今回の目的

- Astra / Codex：体験設計、実装の依頼、レビュー、検証。
- Cursor CLI / Composer 2.5：アプリの実装と修正。別モデルへの自動的な切り替えはしない。
- 企画書.md は企画の原本として保持する。
- 今回はスマートフォン向けアプリの体験をブラウザで触って検証する。ストア公開用アプリや本番サービスの完成は今回の範囲外。

検証する問いは「散歩で撮った植物が庭に増えると、また見つけに行きたくなるか」。

## 一回の体験

1. 自分の小さな植物園を開く。
2. 「植物を見つけた」から撮影・写真選択、またはサンプル写真を選ぶ。
3. 写真と植物名候補、短い特徴を確認する。
4. 候補を選び、「植物園に迎える」を押す。
5. 庭に植物が増え、短い歓迎の演出がある。
6. 庭の植物をタップして、元写真・植物名・発見日・特徴・思い出を見る。

## 比較する見た目

### A：写真の庭

撮影した写真を小さな木の札や押し花帳のようなカードで飾る庭。自分が見つけた記録を眺める喜びを重視する。単なる一覧にせず、余白と配置で小さな植物園として見せる。

### B：絵本の庭（初期表示）

統一した柔らかいイラストの植物が庭に増える。写真は植物を開いたときに見せる。庭の楽しさと発見記録を両立する。植物の素材は用意したサンプルを再利用し、撮影ごとの画像生成は行わない。

両案で同じ収集データを使い、切り替えても植物が消えないこと。比較用の控えめなコントロールで、0種類・3種類・10種類の状態を試せること。サンプル状態の切替で利用者の追加記録を破壊しないこと。

## 世界観

- 仮称「こもれび植物園」。アプリ名は最終決定ではない。
- 静かな庭、やわらかな光、丸みのある植物、深い緑の文字、小さな木の札。
- 配色は草木の緑、アイボリー、土色、花の差し色。
- 既存ゲームの固有キャラクター・画面・ロゴは使わず、穏やかさと収集の喜びを独自の造形で表現する。
- 主役は庭。広告用のヒーロー、機能紹介、巨大なキャッチコピーは不要。
- 日本語の読みやすさを優先。本文16px程度、タップ領域44px以上。絵文字だけで植物素材を代用しない。
- 動きは短く控えめにし、prefers-reduced-motionに対応する。

## 必要な画面と動作

- 庭：A/B切替、植物を選択して詳細、追加導線、発見種類数。
- 写真選択：端末の画像を選択できる。カメラ入力は対応端末で利用可能とし、PCではファイル選択で完走可能にする。サンプル3点以上でも完走できる。
- 判定結果：サンプルの候補選択、短い特徴、戻る、登録。実際のAI識別をしたように見せない。「体験版：判定結果はサンプルです」を入力・結果画面に表示し、偽の信頼度を出さない。
- 登録完了：庭に増えたことがわかる。二重タップで重複登録しない。
- 詳細：実際に選択した写真、種名、日付、短い説明、メモ、再会回数。
- 図鑑：集めた植物を開ける小さな一覧。
- 配置：タップで場所を選ぶなど、スマホで操作できる簡単な移動方式。自由回転や拡大縮小は不要。

## 保存と誠実な表示

- 試作の記録はこのブラウザ内のみ。外部への写真送信や位置情報取得は行わない。
- ページ再読込後も写真、追加記録、メモ、配置が残る。
- 必要に応じ写真を縮小し、保存失敗時は成功と見せず説明を出す。
- 同じ種の再登録は種類数を増やさず、発見記録と再会回数を増やす。
- 種と観察記録と庭の配置を分離し、将来の識別API接続を妨げない。
- サンプルデータとユーザーの追加記録を区別する。
- ログイン、課金、共有、地図、通知、オンラインDB、本物の識別APIは入れない。

## 技術・成果物

- Cursorが既存環境を確認し、軽量なブラウザ試作を実装する。新規ならReact + TypeScript + Vite程度の構成を想定。iOS/Android本番構成はこの試作で固定しない。
- 外部サービスへの公開は今回の作業に含めず、まずローカルプレビューを用意する。
- サンプル画像の出典と使用条件を記録する。画像URLを捏造しない。
- READMEに起動方法、実装済みの範囲、サンプル識別であること、保存の範囲を記載。
- 完了時に変更ファイル、実行した検証、その結果、未完了事項を報告。

## 受け入れ条件

1. スマホ幅で庭が最初に見え、追加操作を始められる。
2. A/Bの見た目が実際に異なり、同じデータで比較できる。
3. 0・3・10種類の庭を試せる。
4. サンプルと自分の画像の両方で、選択→候補→登録→庭→詳細まで進める。
5. 再会と新発見を区別でき、保存・再読込でデータの整合性を保つ。
6. 戻る・キャンセル、保存失敗、画像読み込み失敗で操作不能にならない。
7. 本番ビルドが通り、主要操作と保存の検証結果を残す。
