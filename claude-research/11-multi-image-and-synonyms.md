# 11 — 複数枚送信の効果と、シノニムの落とし穴

**結論（先に3行）**

1. **複数枚送信の効果は確認できませんでした。** 同一記録の3枚を使って 1枚 / 2枚 / 3枚 を比較したところ、種一致は **11/15 → 9/15 → 10/15** と改善せず、むしろ下がりました。ただし後述のとおり**実験の前提が崩れている可能性が高く、公式の主張を否定するには足りません**。
2. **一方で明確な副作用を観測しました：枚数を増やすと `score` だけが上がる。** 平均 0.566 → 0.622 → 0.639。**精度は上がらずに自信だけ上がる**ので、score を閾値に使う設計はますます危険です。
3. **[02](02-taxonomy-backbone.md) の整数照合に穴が見つかりました。Pl@ntNet が返す `gbif.id` は、シノニム側のキーであることがあります。** 同じビワの写真で、1枚目は受容名 `Rhaphiolepis bibas`(10786206)、2枚目以降はシノニム `Eriobotrya japonica`(3024146) を返しました。**対策済み**：50種の照合表にシノニムキーを全部入れました（**1,814キー**）。

**状態**: 完了　**測定日**: 2026-09-08　**消費クォータ**: 45

## 1. 複数枚送信（Q1-1 の残り）

### 方法

GBIF の日本の観察記録から、**同一記録に写真が3枚以上ある15件**を取得。A5 の推奨に従い長辺1280px/q90にリサイズし、`images` を1〜3個送って比較しました（`organs` は枚数分 `auto` を指定）。

### 結果

| 枚数 | 種一致 | 属一致 | top-5 | **平均score** |
|---|---|---|---|---|
| 1枚 | **11/15** | **14/15** | **14/15** | 0.566 |
| 2枚 | 9/15 | 13/15 | 13/15 | 0.622 |
| 3枚 | 10/15 | 12/15 | 12/15 | **0.639** |

### 個別の変化

| id | 正解 | 1枚 | 2枚 | 3枚 |
|---|---|---|---|---|
| M02 | *Melia azedarach* | ✅ 0.980 | ✅ 0.989 | **✗ 棄却** |
| M04 | *Solidago altissima* | ✅ 0.233 | △ *S. odora* | ✅ 0.415 |
| M09 | *Aucuba japonica* | △ *A. chinensis* | △ | **✅ 0.406** |
| M12 | *Rhaphiolepis bibas* | ✅ 0.463 | シノニム名 | シノニム名 |

正解が続いた8件では、score が上がるものがありました（*Fatsia japonica* 0.433→0.618→**0.881**、*Edgeworthia chrysantha* 0.165→**0.735**）。

### この実験の限界（重要）

**公式は「複数枚で結果が改善する」と明記しており、その前提は「同一個体の写真であること」です。** 今回使ったGBIFの市民観察記録の3枚は、その前提を満たしていない可能性が高い：

- 花のアップ・株全体・生育環境、といった**別々の被写体**が混ざる
- 3枚目に**別の植物や風景**が入っている（M02 が3枚で棄却されたのはこれが原因と思われる）
- 器官をすべて `auto` にしているため、本来の使い方（画像ごとに器官を指定）になっていない

→ **「複数枚は効かない」という結論は出せません。** 出せるのは **「雑に複数枚送ると悪化する。同一個体・適切な器官という前提を守る必要がある」** までです。

**UX上の含意**：撮影フローを「同じ株を角度を変えて3枚撮ってください」と設計しない限り、複数枚送信は逆効果になり得ます。安易に「たくさん送れば当たる」という実装にしないこと。

## 2. シノニムの落とし穴（[02](02-taxonomy-backbone.md) への修正）

### 何が起きたか

M12（ビワ）で、**同じ植物・同じ記録なのに、送る枚数によって返る学名とGBIF IDが変わりました**。

| 送信 | Pl@ntNet が返した学名 | `gbif.id` |
|---|---|---|
| 1枚 | *Rhaphiolepis bibas* | **10786206** |
| 2枚 | *Eriobotrya japonica* | **3024146** |
| 3枚 | *Eriobotrya japonica* | **3024146** |

GBIF に問い合わせると：

```
key=3024146  : Eriobotrya japonica   status=SYNONYM   accepted=10786206
key=10786206 : Rhaphiolepis bibas    status=ACCEPTED
```

→ **Pl@ntNet の `gbif.id` は、受容名のキーとは限らず、シノニムのキーが返ることがある。**

[02](02-taxonomy-backbone.md) では「`gbif.id` を整数比較するだけでよい」と書きましたが、**自前テーブルの受容名キーだけを持っていると、シノニム側で返ってきたときに一致しません。**

### 対策（実施済み）

50種それぞれについて GBIF から**シノニムのキーを全件取得**し、照合表に入れました。

| 項目 | 値 |
|---|---|
| シノニムを持つ種 | **48 / 50** |
| シノニムキーの総数 | **1,764** |
| **照合に使う総キー数** | **1,814**（受容名50 + シノニム1,764） |
| CSVサイズ | 37KB |

[`data/species-shortlist.csv`](data/species-shortlist.csv) に `synonymKeys` と `matchKeys` 列を追加しました。**`matchKeys` に含まれるキーのどれかと `gbif.id` が一致すればヒット**、という単純な照合で穴が塞がります。

シノニムが多い種の例：

| 和名 | 学名 | シノニム数 |
|---|---|---|
| ナズナ | *Capsella bursa-pastoris* | **508** |
| ススキ | *Miscanthus sinensis* | 122 |
| カタバミ | *Oxalis corniculata* | 113 |
| ツバキ | *Camellia japonica* | 91 |

ナズナの508件は、19世紀以来この種が何度も別名で記載されてきた歴史そのものです。**文字列で照合していたら絶対に追いつきません。**

### 設計への影響

```
照合の流れ（修正版）：

  Pl@ntNet → results[i].gbif.id
                 ↓
  matchKeys（1,814キー）に含まれるか？  ← 単純な集合の照合
                 ↓ ヒット
  自前の50種のどれか → 和名・特徴・季節
                 ↓ 外れ
  genusKey / familyKey でフォールバック → 「〇〇の仲間」
```

**実行時のネットワーク呼び出しは依然ゼロ**です。ビルド時にGBIFを引いておくだけ。
